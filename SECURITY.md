# Security policy

## Reporting a vulnerability

Do not open a public issue for a security problem. Report it privately
through GitHub's vulnerability reporting for this repository:

<https://github.com/apiarytech/beeguard/security/advisories/new>

(Security tab, "Report a vulnerability". A GitHub account is all that is
needed; there is nothing to sign.)

Include what you can of:

- the version or commit affected, and the platform;
- steps to reproduce, or a proof of concept;
- the impact as you understand it;
- whether you want to be credited, and under what name.

What happens next:

1. You receive an acknowledgement within 7 days.
2. The report is assessed and, if confirmed, fixed on `main` and in the
   next release. You are kept informed in the advisory thread.
3. The advisory is published after the fix is released, with credit to you
   unless you ask otherwise.
4. Until then, please keep the report private. The target for a fix is
   90 days from the report; if it takes longer, you are told why.

## Supported versions

Fixes go into `main` and the next tagged release. Older tags are not
patched; update to the latest release.

## Dependencies

A vulnerability in a dependency belongs to that project. Report it there,
and tell us too so the dependency can be updated.

## Before posting anything public

Issues, pull requests and discussions on this repository are public and
permanent. Do not post credentials, keys, tokens, customer data, plant
tag names, network addresses or anything else you would not publish. If
a report needs such data, use the private channel above.
